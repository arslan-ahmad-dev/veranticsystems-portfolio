PodAgain: AI Learning & Podcast Platform

Podcasts, blogs, PDFs and documents turned into a searchable knowledge base, then into a two-person AI podcast on demand.

MERN · Python · Celery · AWS EC2 · AI

Re-architected for long-running AI work

Users add podcast RSS feeds, blogs, PDFs and documents. The platform transcribes, processes and indexes them, so users can later ask questions or give a prompt and generate a conversational two-host podcast from what they have learned.

The project arrived as a prototype with blocking, synchronous APIs and no real infrastructure for long AI jobs. We rebuilt the foundations and widened what the product could do.

Case study
How we re-architected it +

What we built

  • Queue-based job system. Celery workers replaced blocking requests for ingestion, transcription, content processing, embeddings, vector indexing and audio generation.
  • Leaner GPU server. Business logic moved from the Python AI server into the main backend, so the expensive GPU instance only does GPU work.
  • Smart GPU scheduling. The EC2 GPU instance starts when a job needs it and shuts down after a configurable idle period.
  • Open-source voices. ElevenLabs was replaced with Qwen-based generation for the conversational podcast audio.
  • Credits and billing. Subscription tiers plus usage-based minute credits for transcription, AI voice and audio processing.
  • Retrieval pipeline. AssemblyAI transcripts and document text are embedded into Pinecone for semantic search across everything a user has added.
  • Frontend overhaul. A refreshed interface and a product that now goes well beyond podcasts.

The architecture

  1. FrontendReact app
  2. Node / Express backendauth, billing, business logic
  3. Job queueCelery + Redis
  4. Worker processesingest, transcribe, embed
  5. AI / GPU infrastructurestarted on demand
  6. Vector databasePinecone

Long-running workloads now run independently of user-facing requests, and GPU spend follows actual usage.
