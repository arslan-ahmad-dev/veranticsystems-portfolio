Overview

What it is

A working demonstration built for a surplus-funds recovery firm that was evaluating developers. It downloads the excess-funds lists that counties publish, imports them, and records exactly where each row came from. It was built from public records and synthetic test data only, with no client data. It is a technical demonstration, not a delivered client system.

The problem

Why it was needed

County surplus lists are published as PDFs and spreadsheets in different layouts. Teams chase leads that were already paid or transferred, because a list shows the amount at sale, not what is still held, and there is rarely a trail showing who checked what and when.

Features

What We Built

Live retrieval with provenance

Each file is downloaded from the official page and stored under its hash, with the source link, retrieval time and size recorded.

Import without silent merging

Exact duplicates are skipped and logged; the same parcel sold on different dates is flagged on both sides and kept separate.

Missing values stay visible

A blank surplus or case number is flagged as missing and never turned into zero.

Current-funds gate

A case passes only with a custodian, a confirmed held status, a balance, a source link, an evidence hash and a fresh timestamp.

Tamper-evident audit log

Each entry stores the hash of the one before it, so a forged or edited entry is detected.

Heir and age flags

Owner names containing ESTATE are flagged for research without assuming death, and sale dates are placed in age bands.

Evidence-labelled analysis

Facts are marked verified, unverified or unavailable, and a rule-based GO or HOLD conclusion never turns green on missing proof.

Roadmap

From Idea to Launch

A typical delivery roadmap for a project of this kind.

  1. 1

    Source triage

    1 week
    • List each county source and check what it actually publishes
    • Classify each as machine-readable, staff-assisted or unresolved
    • Agree which sources to automate first
  2. 2

    Connectors

    2-3 weeks
    • Retrieval and parsing for each machine-readable source
    • Row-count checks against the source
    • Change detection between retrievals
  3. 3

    Matching and audit

    1-2 weeks
    • Duplicate and conflict handling
    • Hash-chained evidence log and exports
    • Missing-value flags
  4. 4

    Verification gate

    2 weeks
    • Custodian confirmation workflow for staff
    • Queues for transfers, holds and estates
    • Evidence analysis with a review step
  5. 5

    Sync and launch

    1-2 weeks
    • Push cases and tasks into the client CRM by API
    • Monitoring for broken sources
    • Handover and documentation
